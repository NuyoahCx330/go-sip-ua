## 1. 项目概述

### 1.1 项目定位

本项目是一个**运营商级**SIP协议开发库，使用Go语言实现，作为上层应用的底层基础设施。该库必须提供完整、健壮、解耦的SIP协议实现，**严禁**使用任何简化方案或Demo级别的代码实现。

### 1.2 核心能力矩阵

| 能力域            | 功能要求                              | 优先级 |
| :---------------- | :------------------------------------ | :----- |
| **SIP UA双模**    | 同时作为UAC发起请求和UAS处理请求      | P0     |
| **IMS注册**       | 支持向IMS核心网注册（REGISTER）       | P0     |
| **IMS服务器模式** | 作为P-CSCF/S-CSCF接受话机注册         | P0     |
| **媒体处理**      | SDP协商、RTP流管理                    | P0     |
| **RTP流复制**     | 按需复制指定通话的RTP流到目标地址     | P0     |
| **TLS/DTLS**      | TLS 1.2/1.3, DTLS 1.2 支持            | P0     |
| **SRTP**          | 完整SRTP/SRTCP实现，SDES/DTLS-SRTP    | P0     |
| **音视频编解码**  | Opus/H.264/VP8/G.711/G.722 强制支持   | P0     |
| **代理兼容**      | Kamailio/Asterisk/OpenSIPS 完全兼容   | P0     |
| **事务管理层**    | 完整的事务状态机（INVITE/Non-INVITE） | P0     |
| **传输层**        | UDP/TCP/TLS多传输支持                 | P1     |
| **认证机制**      | Digest认证（RFC 2617），代理认证      | P1     |

### 1.3 设计原则

1. **模块解耦**：各功能模块之间通过明确的接口交互，禁止模块间直接依赖内部实现。
2. **可扩展性**：所有核心组件支持回调注入，允许上层应用定制行为。
3. **生产就绪**：所有代码必须包含完整的错误处理、日志记录、资源管理。
4. **线程安全**：核心API必须支持多goroutine并发调用。
5. **Go惯用法**：遵循Go语言最佳实践，使用`interface`定义契约，`error`处理完善。
6. **运营商级设计**：支持水平扩展、零停机升级、优雅降级。

### 2.2 高并发设计策略

为支持**10万级并发呼叫**，架构必须采用以下设计：

| 策略              | 说明                   | 实现方式                        |
| :---------------- | :--------------------- | :------------------------------ |
| **无锁数据结构**  | 减少锁竞争，提升吞吐量 | 使用sync.Map、原子操作、channel |
| **对象池化**      | 减少GC压力             | sync.Pool复用SIP消息、事务对象  |
| **分片处理**      | 分散热点，线性扩展     | 按CallID哈希分片处理            |
| **异步非阻塞I/O** | 高吞吐低延迟           | 基于epoll/kqueue的事件驱动      |
| **连接复用**      | 减少握手开销           | TLS会话恢复、TCP长连接池        |
| **批量处理**      | 减少系统调用           | 批量读写、批量编解码            |
| **内存池**        | 减少分配开销           | 预分配大块内存，手动管理        |

## 3. SIP UA 双模实现

### 3.1 UAC 模式（外呼发起）

UAC模式允许库作为主叫方发起呼叫，必须支持完整的SIP会话建立流程。

#### 3.1.1 外呼实现要求

text

```
呼叫流程:
1. 应用调用 uac.OutgoingCall() 方法
2. 库构造 INVITE 请求（含 SDP）
3. 通过事务管理层发送 INVITE
4. 处理 1xx 临时响应（100 Trying, 180 Ringing, 183 Session Progress）
5. 处理 2xx 最终响应（200 OK）
6. 发送 ACK 确认
7. 进入会话建立状态
8. 处理会话中的 re-INVITE、UPDATE、BYE
```



#### 3.1.2 UAC 接口定义

go

```
// Package uac 定义UAC（用户代理客户端）接口
package uac

import (
    "context"
    "sip-library/pkg/message"
    "sip-library/pkg/media"
)

// UAC 用户代理客户端接口
type UAC interface {
    // OutgoingCall 发起外呼
    // 10万级并发场景下，调用必须非阻塞，立即返回CallHandle
    OutgoingCall(ctx context.Context, param *CallParam) (CallHandle, error)
    
    // TerminateCall 终止呼叫（发送BYE）
    TerminateCall(ctx context.Context, handle CallHandle, reason string) error
    
    // HoldCall 保持/恢复呼叫（发送re-INVITE）
    HoldCall(ctx context.Context, handle CallHandle, hold bool) error
    
    // ReferCall 转接呼叫（REFER方法，RFC 3515）
    ReferCall(ctx context.Context, handle CallHandle, referTo string, opts *ReferOptions) error
    
    // SendDTMF 发送DTMF（RFC 2833或SIP INFO）
    SendDTMF(ctx context.Context, handle CallHandle, digit rune, opts *DTMFOptions) error
    
    // UpdateMedia 更新媒体（re-INVITE或UPDATE）
    UpdateMedia(ctx context.Context, handle CallHandle, sdp []byte) error
    
    // GetCall 根据句柄获取呼叫对象
    GetCall(handle CallHandle) (Call, error)
    
    // SetCallback 设置UAC事件回调
    SetCallback(cb UACCallback) error
    
    // GetStats 获取UAC统计信息
    GetStats() *UACStats
}

// CallParam 外呼参数
type CallParam struct {
    FromURI             *message.URI
    ToURI               *message.URI
    SDP                 []byte
    Contact             *message.URI
    DisplayName         string
    UserAgent           string
    Supported           []string
    Expires             int
    SessionTimer        bool
    EarlyMedia          bool
    CallingPartyCategory string
    ExtraHeaders        map[string]string
    MaxForwards         int
    // Priority 呼叫优先级（用于QoS）
    Priority            int
    // Timeout 自定义超时
    Timeout             time.Duration
}

// CallHandle 呼叫句柄（使用uint64提升性能，避免字符串分配）
type CallHandle uint64

// Call 呼叫接口
type Call interface {
    ID() string
    Dialog() *DialogInfo
    State() CallState
    RemoteURI() *message.URI
    LocalURI() *message.URI
    GetSDP() []byte
    SetUserData(data interface{})
    UserData() interface{}
    MediaSession() media.Session
    // CreatedAt 呼叫创建时间
    CreatedAt() time.Time
    // Duration 呼叫持续时间
    Duration() time.Duration
}

// CallState 呼叫状态
type CallState int

const (
    CallStateIdle CallState = iota
    CallStateCalling
    CallStateProceeding
    CallStateEarly
    CallStateConnected
    CallStateDisconnected
    CallStateTerminated
)

// DialogInfo 对话信息
type DialogInfo struct {
    CallID      string
    LocalTag    string
    RemoteTag   string
    LocalURI    *message.URI
    RemoteURI   *message.URI
    LocalSeq    int
    RemoteSeq   int
    RouteSet    []*message.URI
    Secure      bool
}

// UACCallback UAC事件回调
type UACCallback interface {
    OnCallStateChange(handle CallHandle, state CallState, oldState CallState)
    OnIncomingResponse(handle CallHandle, rsp *message.Response)
    OnIncomingRequest(handle CallHandle, req *message.Request) error
    OnMediaUpdate(handle CallHandle, sdp []byte)
    OnError(handle CallHandle, err error)
}

// UACStats UAC统计信息
type UACStats struct {
    TotalCalls      int64
    ActiveCalls     int64
    CompletedCalls  int64
    FailedCalls     int64
    AverageSetupTime time.Duration
    P99SetupTime    time.Duration
}
```

### 5.3 媒体处理模式

库支持三种媒体处理模式，适应不同部署场景：

#### 5.3.1 仅信令模式（Signaling Only）

节点仅参与 SIP 信令处理，不建立媒体通道。适用于 SIP 代理、B2BUA 控制节点、注册服务器等场景。

```go
// MediaMode 媒体处理模式
type MediaMode int

const (
    MediaModeSignalingOnly MediaMode = iota // 仅信令，不处理媒体
    MediaModeRelay                          // 媒体转发，不编解码
    MediaModeTranscode                      // 编解码处理
)

// SignalingOnlyConfig 仅信令模式配置
type SignalingOnlyConfig struct {
    // Enable 启用仅信令模式
    Enable bool
    // StripMedia 从 SDP 中移除媒体描述
    StripMedia bool
    // RejectMediaRequests 拒绝包含 SDP 的请求
    RejectMediaRequests bool
}
```

#### 5.3.2 媒体转发模式（Media Relay）

纯媒体转发，接收 RTP 包后直接转发到对端，不进行编解码处理。适用于媒体代理、NAT 穿透、负载均衡等场景。

```go
// RelayConfig 媒体转发模式配置
type RelayConfig struct {
    // Enable 启用媒体转发模式
    Enable bool
    // BufferSize 转发缓冲区大小（字节）
    BufferSize int
    // EnableRTCP 是否转发 RTCP
    EnableRTCP bool
    // EnableFork 是否启用流复制
    EnableFork bool
    // SSRCRewrite 是否重写 SSRC
    SSRCRewrite bool
    // TimestampRewrite 是否重写时间戳
    TimestampRewrite bool
}
```

#### 5.3.3 编解码处理模式（Transcode）

完整编解码处理：接收媒体流 → 解码 → 处理 → 编码 → 发送。适用于媒体网关、录音转码、IVR 等场景。

```go
// TranscodeConfig 编解码处理模式配置
type TranscodeConfig struct {
    // Enable 启用编解码处理模式
    Enable bool
    // InputCodecs 输入端支持的编解码器
    InputCodecs []string
    // OutputCodecs 输出端支持的编解码器
    OutputCodecs []string
    // SampleRate 目标采样率
    SampleRate int
    // Channels 目标声道数
    Channels int
    // FrameSize 目标帧大小
    FrameSize int
    // EnableVAD 启用语音活动检测
    EnableVAD bool
    // EnableComfortNoise 启用舒适噪声生成
    EnableComfortNoise bool
```

### 5.4 自定义请求头处理

支持灵活的 SIP 头域操作，可基于模板动态生成请求头值。

```go
// HeaderRule 头域处理规则
type HeaderRule struct {
    // Action 操作类型：add/set/remove/copy
    Action HeaderAction
    // Name 头域名称
    Name string
    // Value 头域值（支持模板变量）
    Value string
    // SourceHeader 源头域名称（用于 copy 操作）
    SourceHeader string
    // Condition 条件表达式（可选）
    Condition string
}

// HeaderAction 头域操作类型
type HeaderAction string

const (
    HeaderActionAdd    HeaderAction = "add"    // 添加头域
    HeaderActionSet    HeaderAction = "set"    // 设置头域（覆盖）
    HeaderActionRemove HeaderAction = "remove" // 删除头域
    HeaderActionCopy   HeaderAction = "copy"   // 从其他头域复制
)

// HeaderManipulator 头域操作器接口
type HeaderManipulator interface {
    // ApplyRules 应用头域处理规则
    ApplyRules(msg *message.Message, rules []*HeaderRule) error
    // EvaluateTemplate 评估模板表达式
    EvaluateTemplate(template string, msg *message.Message) (string, error)
    // CopyHeader 复制头域值
    CopyHeader(msg *message.Message, from, to string) error
}
```

模板变量支持：
- `${header.Name}` - 引用其他头域的值
- `${uri.user}` - 引用 URI 中的用户名
- `${uri.host}` - 引用 URI 中的主机
- `${method}` - 引用 SIP 方法
- `${callid}` - 引用 Call-ID
- `${from.tag}` - 引用 From tag
- `${to.tag}` - 引用 To tag
- `${timestamp}` - 当前时间戳
- `${random}` - 随机字符串

## 6. RTP 流复制

RTP流复制功能用于合法监听、录音、会议桥接等场景。必须支持动态指定目标地址，非预配置。

go

```
// Package fork 定义RTP流复制接口
package fork

import (
    "net"
    "time"
)

// RTPSession 定义RTP会话接口
type RTPSession interface {
    // StartFork 启用RTP流复制
    StartFork(direction ForkDirection, targets []ForkTarget, streamIndex int) (ForkID, error)
    
    // StopFork 停止RTP复制
    StopFork(forkID ForkID) error
    
    // UpdateForkTargets 更新复制目标
```

## 13. 性能与资源约束（运营商级）

### 13.1 性能指标

| 指标                 | 要求             | 测量条件           |
| :------------------- | :--------------- | :----------------- |
| **并发呼叫数**       | **≥ 100,000**    | 4核CPU，16GB内存   |
| 呼叫建立延迟         | < 100ms          | 不含网络延时       |
| 事务吞吐量           | ≥ 50,000 事务/秒 | 4核CPU，16GB内存   |
| RTP转发延迟          | < 500μs          | 本地转发           |
| SRTP加解密延迟       | < 1ms            | 128字节数据包      |
| 内存占用（空闲）     | < 100MB          | -                  |
| 内存占用（10万呼叫） | < 2GB            | 不含RTP缓冲区      |
| TLS握手时间          | < 30ms           | 本地连接，会话复用 |
| 消息解析延迟         | < 10μs           | 平均SIP消息        |
| GC暂停时间           | < 1ms            | 10万并发场景       |

### 13.2 资源管理要求

1. **内存池管理**：所有SIP消息、事务对象使用预分配内存池，避免频繁GC。
2. **连接池管理**：TCP/TLS连接可复用，支持10万级并发连接。
3. **定时器管理**：使用分层时间轮（Hierarchical Timing Wheel），支持10万级定时器。
4. **RTP Jitter Buffer**：必须提供可配置的抖动缓冲，默认60ms。
5. **编解码器缓存**：频繁使用的编解码器实例缓存复用。

### 13.3 水平扩展策略

| 策略           | 说明                               |
| :------------- | :--------------------------------- |
| **分片路由**   | 按CallID哈希分片，每个分片独立处理 |
| **无状态设计** | 事务状态可序列化，支持故障转移     |
| **连接迁移**   | 支持TLS会话恢复，连接迁移          |
| **负载均衡**   | 支持客户端负载均衡和代理发现       |
